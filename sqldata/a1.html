MySQL Practice Session – Reference Document

Session Overview

This document summarizes the commands executed in MySQL Monitor, their outputs, and the lessons learned. It is designed as a teaching reference for beginners exploring database creation, schema differences, and renaming operations.

1. Starting the MySQL Monitor

Command Prompt Output:
Welcome to the MySQL monitor. Commands end with ; or \g. Server version: 8.0.44 MySQL Community Server - GPL
You successfully logged into MySQL. The monitor provides an interactive shell to run SQL commands.

2. Viewing Existing Databases

SHOW DATABASES;
Lists system databases like information_schema, mysql, performance_schema, sys, and sample databases sakila, world.
SHOW DATABASES displays all databases available on the server.

3. Checking Schemas

SHOW SCHEMAS;
Same list as SHOW DATABASES.
In MySQL, schema and database are synonyms. Unlike Oracle or PostgreSQL, there is no distinction.

4. Creating a New Database

CREATE DATABASE learnSQL;
Database learnsql created successfully.
Always end commands with ;. Database names are case‑insensitive in MySQL.

5. Attempting to Rename Database

ALTER DATABASE learnSQL RENAME TO learnSqlNew; ALTER DATABASE old_db RENAME TO new_db;
Multiple ERROR 1064 (42000) messages indicating invalid syntax.
MySQL does not support renaming databases directly. The ALTER DATABASE ... RENAME syntax is deprecated and removed.

6. Dropping a Database

DROP DATABASE learnsql;
Database deleted successfully.
Use DROP DATABASE carefully—it permanently removes all tables and data inside.

Key Takeaways

  1. SHOW DATABASES vs SHOW SCHEMAS → Same in MySQL.
  2. CREATE DATABASE → Works fine for new databases.
  3. ALTER DATABASE RENAME → Not supported in MySQL 8.0. Direct Rename is not allowed.
    • Workaround: Create a new database and move tables manually or use mysqldump.
    • mysqldump -u root -p learnsqldetail > learnsqldetail.sql  --- Creating backup of the old database in text file format
    • Create New Database
    • mysql -u root -p learnsqldetail2 < learnsqldetail.sql  -- Copying all the data from existing database to new database.
  4. DROP DATABASE → Deletes the existing database permanently.

Difference Between Schema and Database

A database is the overall container that stores and manages data, while a schema is the blueprint or structure that defines how that data is organized inside the database. In simple terms, the database is the "house," and the schema is the "floor plan" that dictates where everything goes

Practical Example (SQL Context)

Database: SchoolDB

Stores all student, teacher, and course data.

Check the List of Schema using following command

show schemas;

Create Schema with the following command

Schema: Create Schema StudentSchema

mysql> create schema studentDetails;
Query OK, 1 row affected (0.01 sec)

Check the Existing Schema weather its created or not use following command

show schemas;

Defines tables like Students, Grades, Attendance.

Another schema in the same database could be TeacherSchema with tables like Teachers, Subjects.

User can create multiple schema within selected database.

This separation allows modularity: multiple schemas can coexist in one database, each serving different organizational needs.

Common Misunderstandings

Schema ≠ Database: Many beginners confuse them because both are related to data organization.

Schema ≠ Table: A schema can contain multiple tables, not just one.

In Oracle, a schema is often tied to a user account, meaning when you create a user, you also create a schema.

Why They Look the Same in MySQL

MySQL treats a schema as a database.

Internally, both commands query the same metadata, so the output is identical.

This design choice comes from compatibility: other systems (like Oracle) use schema to mean the set of objects owned by a user, while MySQL simplifies things by equating schema = database.

How It Differs in Other Systems

Oracle / SQL Server:

  • Database = the whole container.
  • Schema = a namespace inside the database, often tied to a user.
  • Example: In Oracle, HR schema might contain tables like EMPLOYEES, DEPARTMENTS, while another schema SALES has its own tables — all inside one database.

PostgreSQL:

  • Similar to Oracle: one database can have multiple schemas, each grouping related tables.

Key Takeaway

In MySQL, schema and database are interchangeable.

In other RDBMS, schema is a logical subset inside a database, not the same thing.

Since you’re working with MySQL, you can safely treat them as the same. But if you ever switch to Oracle or PostgreSQL, you’ll need to remember that schemas are separate namespaces within a database.

CREATE TABLE

Purpose of the Statement

The CREATE TABLE command in SQL is used to define a new table structure in the database. It specifies the table name, the columns it contains, the data types of those columns, and any constraints (like primary keys or foreign keys).

The UserDetails table is designed to store personal information, preferences, and multimedia data (such as photos) for each user. It includes basic attributes (name, age, gender) along with JSON arrays to handle multiple favourite numbers and colours in a structured way.

CREATE TABLE UserDetails ( Name VARCHAR(50), Age INT(4), Mobile BIGINT(15), NameFirstLetter CHAR(1), Gender BOOLEAN, userPhoto MEDIUMBLOB, Address VARCHAR(200), FavNumber JSON, FavColors JSON );
Query OK, 0 rows affected, 2 warnings (0.11 sec)

CREATING TABLE WITH SAME NAME

If a user attempts to execute a CREATE TABLE statement using a table name that already exists in the database (for example, UserDetails), the database will not allow the operation and will return an error message indicating that the table already exists. Specifically, MySQL will display:

ERROR 1050 (42S01): Table 'UserDetails' already exists

AVOID ERROR WHILE CREATE TABLE WITH SAME NAME USE IF NOT EXISTS

IF NOT EXISTS is a conditional clause in SQL DDL statements, not a datatype. It’s used to safely create objects (like tables or databases) only if they don’t already exist.

Purpose: Prevents errors when creating a table that may already exist.

Behavior:

  • If the table does not exist → it will be created.
  • If the table already exists → MySQL skips creation and does not throw an error.

Example:

Create Table IF NOT EXISTS UserDetails( Name Varchar(50), Age int(4), Mobile Bigint(15), NameFirstLetter char(1), Gender Boolean, userPhoto MediumBlob, Address Varchar(200), FavNumber Json, FavColors Json, MobileModel VARCHAR(34));
